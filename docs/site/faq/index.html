FAQ

Frequently asked questions.

Does MeshCrossway merge Meshtastic and MeshCore into one network?

No. Both mesh networks remain strictly independent. MeshCrossway never bridges, relays, translates, synchronizes or cross-sends messages between them; a shared UI does not combine protocol identities.

Can both networks operate at the same time?

Not through the current Core firmware. The architecture has two autonomous radio Pods, but v0.7.6 supports only one active BLE session. Independent simultaneous authenticated sessions, Meshtastic PhoneAPI messaging and coexistence testing remain planned.

Does it need cellular service or internet?

The field experience is designed to be offline-first. Internet may be useful for development, firmware downloads or future data services, but basic LoRa mesh operation is not intended to depend on it.

Is the hardware finished?

No. The selected Waveshare Core and two XIAO/Wio LoRa Pods form a modular three-device plan; battery design, BLE coexistence, RF and GNSS hardware are still being verified. The old common-carrier UART PCB is archived.

Can I try the interface?

Yes. The browser UI simulator is available from this site and uses sample data. It is a design prototype, not a connection to real radios.

Can I flash firmware from the browser?

Yes, for the supported Waveshare ESP32-S3-Touch-LCD-3.5 Rev2.0 non-B Core. It dynamically lists published builds, preselects the last owner hardware-tested version (v0.6.8 at this snapshot), warns before experimental installs and does not flash the two native radio Pods.

Are messages stored securely on microSD?

Not yet. Chat history is not a persistent encrypted vault. Read-only eFuse diagnostics are present, but encryption and the SD journal are paused in unmerged development PRs pending explicit authorization. An existing FAT32 Wi-Fi backup can contain plaintext credentials.

Is MeshCrossway an emergency or rescue device?

No. It is experimental open-source hardware/software and should not be relied on as the sole communications method for safety-critical use.
