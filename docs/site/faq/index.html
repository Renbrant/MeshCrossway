FAQ

Frequently asked questions.

Does MeshCrossway merge Meshtastic and MeshCore into one network?

No. V1 uses two independent radios and preserves each protocol's identity, security and routing. The unified UI is not an automatic protocol bridge.

Can both networks operate at the same time?

Yes. The controller supports simultaneous independent Meshtastic and MeshCore BLE radio sessions. Broader RF coexistence, range and endurance qualification of the final hardware remains ongoing.

Does it need cellular service or internet?

Native LoRa messages and local GNSS/track tools do not require cellular service. Previously cached SD map tiles work offline; downloading uncached tiles and firmware needs Internet access.

Do I have to use a Seeed XIAO/Wio radio?

No. The radio hardware is user-selectable. Heltec V3 is the current development-tested setup. Each chosen device must support the corresponding native Meshtastic BLE PhoneAPI or MeshCore BLE Companion with compatible firmware; compatibility is checked per model and firmware.

Is the hardware finished?

The working software uses a Waveshare touchscreen controller and two independent BLE radios. Final detachable Pod power, enclosure, RF and environmental validation remain in progress. The integrated Rev A PCB is an archived design.

Can I try the interface?

The interactive browser simulator has been retired because it no longer reflects the current firmware. Product photos and operation screenshots on the project page show the available real-device evidence.

Can I flash firmware from the browser?

Yes. The Web Flasher installs v0.9.28 stable on the supported non-B Waveshare ESP32-S3-Touch-LCD-3.5 Rev2.0. v0.9.25 and v0.9.16 remain recovery choices. Each image is checksum-verified.

Is MeshCrossway an emergency or rescue device?

No. It is experimental open-source hardware/software and should not be relied on as the sole communications method for safety-critical use.
